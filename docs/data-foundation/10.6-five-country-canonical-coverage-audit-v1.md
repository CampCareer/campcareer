# 10.6 Five-Country Canonical Coverage Audit & Expansion Plan v1

Date: 2026-08-02
Branch: `audit/five-country-canonical-coverage-v1`
Status: **Read-only audit complete** — no database writes, no migrations, no production changes.

## Purpose and scope

This audit establishes the canonical coverage of the five target countries — `AU`, `GB`, `US`, `CA`, `IE` — across the repository's data layers, database schemas, runtime surfaces, and official source systems, and produces the evidence needed for a future 10.7 expansion. Product-facing `UK` input is normalized to canonical `GB` per `src/lib/data-foundation/country-normalization.ts`.

The audit is strictly read-only. All database observations were made through the PostgREST REST API using the service-role key for `SELECT`/`COUNT` only; the service-role key is never exposed and no production object was modified.

## Executive verdict

**C — Covered with gaps (no release-blocking findings).**

The canonical schema foundation (`core`, `catalog`, `taxonomy`, `evidence`, `labour`, `reporting`, `ingest`, `api_private`) is structurally ready from migration analysis, and every five-country entity family has observed public-view rows for institution and course data. The binding constraints are data coverage, not schema readiness:

- No `US` or `IE` canonical occupation tables exist (`occupations_us`, `occupations_ie` absent).
- No raw snapshot folders exist in `data/raw/` for any of the five canonical countries.
- The origin-comparison runtime dependency tables return `404` via REST and exist only in migration `20260712121724`.

## Method

1. **Repository inventory** — enumerated `data/raw`, `data/canonical-candidates`, `src/data` fixtures, and `scripts/` importers.
2. **Database observation (read-only)** — captured the `public` schema OpenAPI (86 paths) via PostgREST and ran exact `COUNT` probes for all 85 public tables/views (`data/audits/five-country-canonical-coverage/2026-08-02/scripts/count_public_tables.sh` → `public_schema_counts.tsv`). Counted all 12 `api_private` views.
3. **Schema analysis** — read report-factory migrations (`20260730172000`, `20260730180000`, `2026073018100x`, `20260730183000`, `20260730211500`) to enumerate canonical schemas and the public-view restoration layer.
4. **Runtime surface audit** — mapped every Supabase call site (`src/app`, `src/lib`, `src/components`) to its data layer: `STATIC_FIXTURE`, `PUBLIC_TABLE`, `PUBLIC_VIEW`, `SERVICE_ROLE`, `API_PRIVATE`, `AUTH_SCOPED`, `EXTERNAL`.
5. **Official source research** — verified canonical sources for each country on the web.

## Observation scope and limitations

PostgREST exposes only `public`, `graphql_public`, and `api_private`. The canonical schemas (`core`, `catalog`, `taxonomy`, `evidence`, `labour`, `reporting`, `ingest`, `retired`) are **not exposed to PostgREST**; they were assessed statically from migration SQL only. Row counts reported here are from the public view layer over `ingest.*` (restored by `20260730183000_restore_public_access.sql`), which is what the REST API can observe.

## Runtime surfaces

- `/map` legacy + `/maps` canonical: `getInitialMapShellData` (`revalidate 86400`) populates only the AU bundle; other countries are lazy-loaded or static JSON bundles (`src/data/*-map-data.ts`).
- `/au/jobs/[jobname]` is the densest DB surface (10 service-role tables).
- Workspace `/compare` consumes the `api_private` Nursing read model via `AU_NURSING_PROGRAM_COMPARE_REPOSITORY`; country compare matrices use static fixtures.
- Origin comparison (`src/lib/study-product/origin-comparison.ts`) reads four tables that return `404` via REST — **runtime risk** (see GAP-007).
- External proxies (Adzuna, Frankfurter FX, data.go.kr) have no DB dependency.
