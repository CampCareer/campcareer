## Purpose and scope

This audit establishes the canonical coverage of the five target countries — `AU`, `GB`, `US`, `CA`, `IE` — across the repository's data layers, database schemas, runtime surfaces, and official source systems, and produces the evidence needed for a future 10.7 expansion. Product-facing `UK` input is normalized to canonical `GB` per `src/lib/data-foundation/country-normalization.ts`.

The audit is strictly read-only. All database observations were made through the PostgREST REST API using the service-role key for `SELECT`/`COUNT` only; the service-role key is never exposed and no production object was modified.

## Executive verdict

**B. Conditional Pass** (revised by 10.6A; original 10.6 verdict `C — Covered with gaps` withdrawn).

Meaning:
- Public/legacy data status is **confirmed** (observed via PostgREST public views over `ingest.*`).
- The canonical schema foundation (`core`, `catalog`, `taxonomy`, `evidence`, `labour`, `reporting`, `ingest`, `api_private`) is structurally ready **from migration analysis only** — canonical tables are **not exposed to PostgREST** and no direct read-only database connection was used, so **canonical database counts were NOT observed** (`canonical_database_count: null`). Structural verification via admin-only read-only audit tooling is WP-01.
- 10.7 preparation can start; production data import only after prerequisite checks.

Binding constraints (unchanged by correction):

- No `US` or `IE` canonical occupation tables exist (`occupations_us`, `occupations_ie` absent).
- No tracked source lineage (manifests/checksums) exists for the five canonical countries.
- The origin-comparison runtime dependency tables return `404` via REST and exist only in migration `20260712121724` (see GAP-007 verification below).

## Method

1. **Repository inventory** — enumerated `data/raw`, `data/canonical-candidates`, `src/data` fixtures, and `scripts/` importers.
2. **Database observation (read-only)** — captured the `public` schema OpenAPI (86 paths) via PostgREST and ran exact `COUNT` probes for all 85 public tables/views (`data/audits/five-country-canonical-coverage/2026-08-02/scripts/count_public_tables.sh` → `public_schema_counts.tsv`). Counted all 12 `api_private` views.
3. **Schema analysis** — read report-factory migrations (`20260730172000`, `20260730180000`, `2026073018100x`, `20260730183000`, `20260730211500`) to enumerate canonical schemas and the public-view restoration layer.
4. **Runtime surface audit** — mapped every Supabase call site (`src/app`, `src/lib`, `src/components`) to its data layer: `STATIC_FIXTURE`, `PUBLIC_TABLE`, `PUBLIC_VIEW`, `SERVICE_ROLE`, `API_PRIVATE`, `AUTH_SCOPED`, `EXTERNAL`.
5. **Official source research** — verified canonical sources for each country on the web.

## Observation scope and limitations

PostgREST exposes only `public`, `graphql_public`, and `api_private`. The canonical schemas (`core`, `catalog`, `taxonomy`, `evidence`, `labour`, `reporting`, `ingest`, `retired`) are **not exposed to PostgREST**; they were assessed statically from migration SQL only. All row counts in this audit are **`public_legacy_view_count`** (PostgREST public views over `ingest.*`, restored by `20260730183000_restore_public_access.sql`) or **`api_private_read_model_count`**. They are **NOT canonical database counts** and must not be combined with canonical counts. No `canonical_database_count` exists in this audit (all `null`).

## GAP-007 verification (added by 10.6A)

Determination: **`migration_not_applied`** + **`runtime_graceful_degradation_verified`**.

- Migration `20260712121724_global_comparison_and_leads.sql` creates all four tables (`concept_career_mappings`, `career_compensation_observations`, `housing_cost_observations`, `country_comparison_coverage`) in `public` with RLS + `service_role` grants.
- All tables from migrations `20260711194734` and `20260712121724` return `PGRST205` ("Could not find the table ... in the schema cache") — including `decision_plans`, `plan_save_intents`, `canonical_concepts`, `course_offerings`, `taxonomy_nodes` — while control tables (`saved_pathways` = 200, `data_source_runs` = 206) respond, proving the migrations were **not applied** in production.
- Runtime degrades gracefully: `origin-comparison.ts` queries via `supabaseAdmin` against `public` inside try/catch and returns `unavailable()` on error; it does not throw. `plan-service.ts` reads `plan_save_intents` (same root cause).
- GAP-007 stays **P1 runtime risk, not a release blocker**. Verify at runtime before 10.7 ingestion (WP-05) and record apply-migration / backfill / de-scope decision.
