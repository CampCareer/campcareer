## 5. Reusable tooling

Runner: `scripts/data-foundation/run-canonical-read-only-audit.sh`

- **No DB URL argument.** Connection is taken only from allowlisted env vars: `SUPABASE_DB_URL`, `DIRECT_URL`, `DATABASE_URL`, `POSTGRES_URL`. Secrets are never printed.
- **Read-only enforcement:** verifies `transaction_read_only = on` inside `BEGIN TRANSACTION READ ONLY ... ROLLBACK`; each SQL file runs in its own READ ONLY transaction that always rolls back. `SET LOCAL statement_timeout='120s'`, `SET LOCAL lock_timeout='5s'`.
- **SQL file allowlist:** only the six `sql/*.sql` files may be executed; schema identifiers are checked against the canonical allowlist before building `count(*)` queries.
- **Forbidden-statement gate:** rejects any non-comment line beginning with `insert/update/delete/upsert/merge/truncate/alter table/create table/drop table/grant/revoke/copy/call/do/vacuum/analyze/refresh/commit`.
- **Exact counts only** (`select count(*)`), never `pg_class.reltuples` estimates.
- **Exit codes:** `0` success; `1` failure; `2` no-access (skeleton artifacts, verdict-B path); `3` partial (some SQL files failed).
- **Output:** configurable via `AUDIT_OUTPUT_DIR` (default `data/audits/canonical-read-only-observability/<date>`); `AUDIT_SQL_DIR` configurable.
- **No write capability:** cannot run migrations, import data, or write to the database.

Static manifest `scripts/data-foundation/canonical-tables.json` enumerates the 87 canonical tables from migration SQL analysis (`20260730172000`, `20260730180000`, `20260730181002-06`, `20260730181014`, `20260730211500`). It is used only for the no-access observation layer and is never a substitute for live schema inventory.
