## 3. WP-01 — Canonical read-only audit observability (P0)

**Corrected direction.** Do NOT expose canonical schemas to PostgREST, grant public/anon/authenticated `SELECT`, create `select-*` public views, or allow browser access. Instead:
- psql **read-only connection** (or Supabase SQL editor `SELECT`-only), or an **admin-only audit script**;
- run in a **`READ ONLY` transaction**;
- use **schema-qualified counts**;
- **save audit result files** (manifest, checksums, counts);
- **no credentials or raw rows saved**.

Acceptance: canonical schemas stay private; admin-only read-only row counts collectible; no new browser/PostgREST exposure; no privilege expansion.

## 4. WP-03 — Three-tier raw snapshot policy (P0)

**Tier A — Git:** manifest, metadata, download URL, `retrieved_at`, checksum, file size, licence, parser version, schema version, sample fixture, validation report.

**Tier B — Object storage / controlled artifacts:** large raw `CSV/XLSX/ZIP/JSON-bulk/HTML/PDF` snapshots.

**Tier C — No storage (re-download only):** no-redistribution licences, authenticated/temporary URLs, ToS-restricted sources. Git still receives manifest + retrieval instructions + checksums.

Recommended layout: `data/source-manifests/{country}/{source}/`. **Success criterion = reproducible source lineage**, NOT existence of a `data/raw/{country}` folder.

## 5. GAP-007 verification result

Determination: **`migration_not_applied`** + **`runtime_graceful_degradation_verified`**.

- `supabase/migrations/20260712121724_global_comparison_and_leads.sql` creates all four tables (`concept_career_mappings`, `career_compensation_observations`, `housing_cost_observations`, `country_comparison_coverage`) in `public` with RLS + `service_role` grants.

Control tables respond: `saved_pathways` = 200, `data_source_runs` = 206. No drop-migration exists; hardening migrations do not touch these tables. Conclusion: migrations **not applied** in production.
- Runtime: `src/lib/study-product/origin-comparison.ts` uses `supabaseAdmin` against `public`, wraps queries in try/catch, and returns `unavailable()` on error — **graceful, does not throw**. `src/lib/study-product/plan-service.ts` reads `plan_save_intents` (same root cause, also 404).

GAP-007 stays **P1 runtime risk, NOT a release blocker**. Verify at runtime before 10.7 ingestion (WP-05) and record apply-migration / backfill / de-scope decision.
