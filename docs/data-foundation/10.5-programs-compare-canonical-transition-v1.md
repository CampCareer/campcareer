# 10.5 Programs Compare canonical transition v1

Date: 2026-08-02
Branch: `feat/programs-compare-canonical-transition-v1`

## Purpose and launch scope

Programs Compare now consumes a generic, source-aware DTO. The first applied vertical is the three existing Australia Nursing products. The same contract is intended for Australia, Great Britain, United States, Canada, and Ireland, while product-facing UK input is normalized to canonical `GB`.

This transition does not add data for GB, US, CA, or IE and does not change Countries, Cities, Careers, Maps, Home, authentication, saved pathways, ROI, ranking, or canonical database objects.

## Generic DTO and repository boundary

`src/lib/data-foundation/program-compare-contract.ts` defines the generic `ProgramCompareItem`, value status contract, source reference, and repository interface. It contains no Nursing, AU, CRICOS, or provider-specific fields. `country-normalization.ts` accepts product and display aliases and emits only `AU`, `GB`, `US`, `CA`, or `IE` canonical codes.

`AU_NURSING_PROGRAM_COMPARE_REPOSITORY` is a server-only implementation. It uses explicit projections from the narrow canonical `api_private` Nursing read models because the generic `au_program_catalog_v1` view does not expose the canonical programme/offering UUID pair required by this vertical. Raw rows never cross the server/client boundary; the client receives only the sanitized generic DTO.

## Canonical transition

The three fixed product IDs resolve to their existing canonical programme and offering UUIDs. The repository selects the exact international offering, current verified tuition evidence, and reviewed entry requirements. Missing values remain null and render as `Unavailable`; no fixture value is used as a fallback. The UI intentionally omits the v1-excluded professional outcome, accreditation, placement cost, registration, visa, employment, ROI, and ranking fields.

The official provider page, reviewed date, and verification status are exposed as the source section. Snapshot hashes, evidence IDs, raw extracts, and internal review fields remain server-side.

## Fixture retirement policy

The Programs Compare runtime imports neither the Home fixture nor the 10.4C candidate files. The candidate package remains an audit artifact. Fixture files elsewhere in the repository may remain for non-runtime tests or other product surfaces, but they are not consulted by the target `/compare?type=program` path.

## Security and failure policy

The repository imports `server-only` and uses the existing server Supabase client for SELECT projections only. There is no browser request to `api_private` or canonical schemas, no service-role client in a client component, no public compatibility fallback, and no raw canonical row serialization. Unknown, unresolved, unsupported, and server failures produce controlled unavailable DTOs rather than database errors.

## Extension path

Future `GreatBritainProgramCompareRepository`, `UnitedStatesProgramCompareRepository`, `CanadaProgramCompareRepository`, and `IrelandProgramCompareRepository` implementations can satisfy the same interface and adapter contract. They must provide exact canonical identity resolution and value-level sources before being enabled; no guessed identifiers or fixture placeholders are permitted.
