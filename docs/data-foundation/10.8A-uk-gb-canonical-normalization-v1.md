## 1. Verdict

**Case A confirmed**: The `core.countries` table contains a row with code `UK` but no row with code `GB`. The migration candidate normalizes `UK` → `GB` across all database references.

The migration candidate is a **dry-run only** — no production database modifications were made. The rollback candidate is provided for emergency reversal.

## 2. Scope

- DB schema audit of `core.countries`, FK references, and JSONB metadata columns
- Migration candidate SQL (`migration_candidate.sql`) covering all UK→GB changes
- Rollback candidate SQL (`rollback_candidate.sql`) for reversal
- Dry-run report (`dry_run_report.json`) documenting pre/post migration state
- Validation report (`validation_report.json`) confirming all checks pass
- Application code impact assessment (18 files using `UK` as country code)

## 3. Database Findings

No `GB` row exists. The migration candidate updates the `code` from `UK` to `GB`.

## 4. Migration Candidate

The migration candidate (`migration_candidate.sql`) performs the following operations inside a `BEGIN`/`COMMIT` transaction:

1. **UPDATE core.countries**: Change `code` from `UK` to `GB`
2. **UPDATE core.geographies**: Change `country_code` from `UK` to `GB` (37 rows)
3. **UPDATE core.qualification_frameworks**: Change `country_code` from `UK` to `GB` (1 row)
4. **UPDATE public.campuses**: Change `country_code` from `UK` to `GB` (50 rows)
5. **UPDATE public.institutions**: Change `country_code` from `UK` to `GB` (50 rows)
6. **UPDATE public.outcome_observations**: Change `country_code` from `UK` to `GB` (140 rows)
7. **UPDATE public.occupations**: Change `country_code` from `UK` to `GB` (408 rows)
8. **UPDATE public.country_pr_pathways**: Change `country_code` from `UK` to `GB` (1 row)
9. **UPDATE JSONB metadata**: Set `metadata->>'country'` from `UK` to `GB` in all 6 tables

## 5. Rollback Candidate

The rollback candidate (`rollback_candidate.sql`) reverses all 9 operations, restoring `UK` as the country code in all tables and JSONB metadata.
