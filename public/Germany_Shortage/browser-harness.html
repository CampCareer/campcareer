browser-use / browser-harness

A thin, editable CDP harness that lets an LLM
drive your real browser directly.

One websocket to Chrome, nothing between. The agent writes what's missing during execution and saves it for next time — the harness improves itself every run.

~1k lines · 4 core files Python (upstream) · TS (in BrowserCode) Works with Claude Code / Codex Self-healing helpers
The promise

Browser ability and code-writing ability are deeply connected. Turn browser interaction into a coding problem — the agent writes JavaScript that drives Chrome through CDP. Minimal abstractions. Maximal power.

Philosophy

Do more with less

No high-level "click button by selector" DSL. The LLM writes CDP calls (or imports a tiny helper it wrote last week). Anything the model can express in JS, the browser can do.

The self-healing loop
1. need
Agent wants to do X
(upload file, paginate, scrape...)
2. check
Helper missing in agent_helpers.py
3. write
Agent writes the helper itself
4. run
CDP call executes in real Chrome
5. persist
Helper saved — next run is faster

The harness isn't a library the agent imports; it's a workspace the agent extends. Helpers and domain skills (site-specific flows) are written by the agent itself, not hand-authored.

Three ways to connect

Way 1 Real profile

Your running Chrome

Connect to the user's actual logged-in browser. Ticking "Allow remote debugging" in chrome://inspect/#remote-debugging is the only setup. Click "Allow" once on the Chrome 144+ per-attach popup. 

await session.connect()
Way 2 Isolated profile

Local Chrome, debug port

Launch your own Chrome with --remote-debugging-port + a custom --user-data-dir. No popups, no shared cookies. Good for unattended automation and QA. 

google-chrome --remote-debugging-port=9222 \
  --user-data-dir=./.bcode/chrome-data-dir
Way 3 Remote

Browser Use Cloud

Provision a cloud browser via the v3 API. Free tier includes stealth, captcha solving, proxies. The agent can sign up autonomously if no API key is set. 

POST /api/v3/browsers → cdpUrl
GET ${cdpUrl}/json/version → wsUrl
await session.connect({ wsUrl })
agent-workspace

Reusable helpers

Generic browser primitives the agent writes once and re-imports: click_by_text(), wait_for_url(), upload_file(), etc. Cache-bust imports with ?t=${Date.now()} so edits are picked up.

domain-skills

Site-specific playbooks

Site flows (LinkedIn outreach, Amazon ordering, expense filing...). The agent writes these itself when it figures out a non-obvious selector or edge case. Enable with BH_DOMAIN_SKILLS=1.

The single primitive

BrowserCode vendors a TypeScript port of Browser Harness and exposes it as one tool call. Same model — just the JS dialect of the same Python harness. 

browser_execute(code)
  → runs JavaScript in-process
  → talks to Chrome through the DevTools Protocol
  → keeps the browser session alive across calls
  → returns logs, values, and screenshots to the agent
